# 研究与证据规范

本文件约束结构化研究数据；原版保真重放不冒充逐值证据重验，也不自动授予发布、上传或付费权限。
先明确商业问题、研究对象、地域、时间和要支持的决定，再采集材料。
研究数据是事实与判断的来源；报告配置只负责选择和展示，不另造事实。

## 来源和原文

1. 先读获准原始材料，登记可读范围、缺页和版本，不能用摘要代替完整原文。
2. 外部研究优先用可用 Tavily 发现来源，关键结论回官方或一手原文；不可用时记录替代检索方式。
3. `sources` 分开记录发布日期、采集日期和数据时期，不用今天的日期覆盖历史观察。
4. `source_kind` 可为 `original`、`search_summary`、`client_statement`。搜索摘要只作线索，客户原话只能证明客户说过什么。
5. 每条证据保留 `original_location`，或通过来源 `original_location`、访谈 `record_location` 回查页码、表号、段落或归档位置。
6. 没有披露的信息如实写“未披露”。这不是已补证，也不解除比较限制。

## 证据类型

所有类型共同保存：`evidence_id`、`question_ids`、`source_id`、`evidence_type`、`claim`、`claim_type`、`limitations`、`review_status`。
数值可写入 `value`，必须同时有 `unit`；商品标价已有独立数值字段。编号必须唯一，引用必须真实存在。

### 消费者调查 consumer_survey

必填 `sample_size`（正整数）、`population`、`method`、`survey_period`、`question_wording`、`response_mode`、`weighting`、`error_information`。
`response_mode` 为 `single`、`multiple` 或 `open`。调查方法说明招募方式及样本偏差。
未披露加权或误差信息可明确登记并产生警告；缺样本量不能捏造数字来通过检查。
评论、社群反馈或少量访谈不是总体抽样，不能包装成“消费者有多少比例”。
公开调查不得描述为客户专项调查，多选比例不能不加说明画成合计100%的构成图。
调查证据可额外登记 `denominator`（分母定义）和 `denominator_count`（正整数分母人数）。普通调查记录可暂缺；进入调查饼图时必须齐全，并与各项调查口径一致。
`sample_size` 是调查样本量，不自动等于本题有效分母。统计卡的样本、对象、时期和原始问法必须由所引调查原样填写；多选和开放题不能使用饼图。

### 商品观察 product_observation

必填 `brand`、`product`、`merchant`、`specification`、`quantity`（正整数）、`observed_price`、`currency`、`promotion_eligibility`、`shipping`、`region`、`stock_status`、`observed_at`、`entry_point`。
本类型不要求消费者调查样本量。价格必须说明规格、件数、销售主体、地区、日期、运费与优惠资格。
关键比较条件缺失时禁止价格比较；“标价、不含运费”和“到手价”不能直接混比。
一次观察不能推出持续趋势、总体偏好、渠道利润或复购表现。

### 企业披露 company_disclosure

必填 `publisher`、`self_reported`、`document_title`、`report_period`、`definition_scope`、`original_location`。
披露期与发布日期分开。保留企业自报范围与合并口径，不强制添加调查样本量。
单一企业经营表现不能直接推广为行业规律。

### 机构公开材料 public_document

政府政策、行业协会及公共机构指导材料使用此类型，不误标为企业自报。
复用文件披露字段 `publisher`、`document_title`、`report_period`、`definition_scope`、
`original_location`，并明确 `self_reported: false`。文件观点不自动等同于独立统计数据，
有统计总体、分母和方法的数值应优先按行业统计登记；健康指导也不证明购买意愿。

### 行业统计 industry_statistic

必填 `statistical_agency`、`definition`、`population`、`geography`、`period`、`unit`、`denominator`、`method`。
统计总体、品类边界和分母必须清楚，不用总市场规模替代细分品类容量。
不同统计口径只能注明差异，不能拼接成连续增长趋势。

### 定性访谈 qualitative_interview

必填 `participant_role`、`participant_count_or_selection`、`interview_date`、`record_location`、`anonymity`、`excerpt_or_observation`。
原话、研究者观察和解释分开。允许按角色选择的少量访谈，不编造统计误差或总体比例。
客户陈述使用 `claim_type: client_statement`，不靠设置 reviewed 把经营自报变成外部事实。

### 计算推导 derived_calculation

必填 `input_evidence_ids`、`formula`、`conversions`、`assumptions`、`unit`、`rounding`、`comparison_conditions`。
`claim_type` 使用 `judgment`，不能标为原始 `fact`。数值图需要额外登记复算后的 `value`。
输入证据递归回查来源和复核状态；自引用、循环、悬空引用均拒绝。
独立 `calculations` 也保存输入、公式、换算、假设、单位、舍入与比较条件；可登记 `result`、`review_status`。
公式是追溯文本，校验器不使用 eval，不执行公式，不从字符串自动推算结果。
独立复算才是结果正确性的证据；脚本只检查记录完整与数值引用是否对应。

## 食品研究的五条线

- 行业价值链：原料、加工、物流、渠道与终端的对象和时期分别记录，不混淆出厂价与零售价。
- 竞品与渠道：同规格、同购买资格、同地区、同日期比较，区分铺货观察与真实销量。
- 产品与体验：配料、营养、保质期、口感和使用条件分别取证；包装宣称不等于独立验证。
- 消费者与需求：区分购买者、食用者和推荐者；说明问题问法与样本边界。
- 客户经营联系：结论落到需要讨论的产品或渠道决策，但缺乏客户数据时不补写收入与利润承诺。
- 缺少直接的消费者、商品或渠道验证时，产品和渠道排序只能列为有条件的待验证假设，明确能使其成立或被否定的下一步证据。

## 验证入口与结果

```sh
node scripts/验证研究数据.cjs 研究数据.json [报告.json]
```

程序接口：`validateResearch(research, report = null)` 返回 `{ok, counts, bySeverity, issues}`。
`issues` 每项带 `severity/file/path/code/message/suggestion`；`counts` 为各级数量，`bySeverity` 为分类数组。
标准输出为 JSON，标准错误输出为人类可读说明；存在 `fatal` 时退出码1，否则0。
恶意或非 JSON 形状返回 fatal，不向调用者抛异常；不执行访问器、toJSON 或公式。

- `fatal`：结构缺字段或类型错误、未知证据类型、编号重复、悬空引用、来源断裂、错误事实升级、对客门禁未达标。
- `warning`：结构合法的内部研究仍待补分析、待复核、调查误差未披露、非关键研究问题未回答。
- `info`：企业自报提示、公式不执行提示、机器校验不等于人工内容验收。

结构必填与研究完成度是两层要求：研究阶段可以使用空证据集合、待补的分析字段或 draft 状态，但不能保留伪造的编号、错误类型或缺失的类型必填字段。
