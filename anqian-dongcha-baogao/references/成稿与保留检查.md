# 成稿与保留检查

用于两种模式的新研究和内容修订；纯格式转换、历史保真回放不强行重排。这里检查表达与覆盖，不提高原始资料的证据等级。

## 从问题到客户阅读

先读原研究问题及每个必要子项，在项目内写`成稿核对.json`。例如“渠道利润”可能同时要求费用、促销频率、账期和退货；不能用“已讲渠道”代替逐项处理。每项能回答就给出报告位置，不能回答就明确缺什么材料及影响哪个决定。

修订已有报告时，再列出其值得保留的具体内容及新位置。舍弃错误、重复或不相关内容应写理由，不为“保留完整”延续错误。没有获准读取旧稿的独立测试，只依据原输入列清单，由后续审查者比较旧稿，不偷看答案。

机会研究应有一页可扫描的方向总览：谁在什么场景需要什么、成立条件、主要风险，以及下一步验证。企业能力路线不能代替机会方向，机会方向也不能当作已证实的投入排序。资料不能支持排序时，平行呈现条件而非删除选项或伪造优先级。其他题目按实际决策需要组织，不强塞食品清单。

每页主线是发现、依据、为何如此、经营含义。重要的不成立条件留在正文；重复的检索过程、证据登记说明和自我提醒进入备注或底稿。方法与验证页只有在能改变决策时才独立保留。底稿不是遗漏正文推理的借口，附录保持精简但不删依据。

## 图形选择与阅读

- 硬门槛：完整主报告至少三分之二的实际物理页以实质图表为主。执行[图表占比验收](图表占比验收.md)，逐页登记并独立复核；不合格或待确认不计入，比例不足不能判成稿完成。文字框、纯文字表格和组件名称不能冒充合格图表页。
- 在项目内写`逐页图形方案.json`：每页记录页码和页面ID、角色、核心结论、证据或带边界的待验证假设、图形形式、真实维度、使用的数据或关系材料、读图所得、必要解释、经营含义、客户页限制、预计分类和理由。预计页数必须包含自动目录、来源索引、结尾和合并附录。先运行`检查图表方案.cjs`；不通过就调整结构，不生成整稿。
- 连续可比数据才画趋势或统计比较，不同单位不得用无公式的相对柱高。
- 口径不同不等于一律取消图表：可分别成图、各标单位和样本，明确不能合并或排序。调查摘录缺样本和时期时只能作历史线索，缺失项留在图旁，不把精致图形当作证据补全。
- 有顺序或约束关系用步骤图；任务、形态或渠道的条件差异用并列比较；机会用方向与条件分组。优先实际HTML文字，手机自动重排，不把全页分析烘焙成一张图片。
- 控制机制图要画清“前后顺序、控制动作、守住什么、失控后果”；箭头只表达有依据的关系，待验证的机制明确标注。只有并排标题、段落和颜色，没有可直接读取的关系，仍按文字页审查。
- 表格适合精确查数、跨维度逐项对照；连续三页及以上以表格为主时复核讲述节奏。改变结构必须让关系更清楚，不能只加边框或换类名。
- 图片用于真实商品、原件或确需保留的图像。内含小字时提供可读的正文解释或改为可重排图形；放大图片不能代替默认阅读验收。不能删掉微生物、工艺、制造或经营核查细项，仅留下几个大框来冒充完整。
- 兼容新稿可用`diagram`块，结构化稿可用已存在的`visual_layout`。具体契约见`报告原型与版式.md`。桌面/PDF与390宽手机逐页看，关键图形文字至少14px；不通过压缩字体、裁切文字或装饰图掩盖问题。

## 核对文件

字段示例仅示意结构，真实条目必须来自获准输入，不复制示例当研究成果：

```json
{
  "requirements": [
    {"id":"Q1.a","text":"需要比较的具体子问题","source_location":"原问题清单第1项"}
  ],
  "coverage": [
    {"requirement_id":"Q1.a","page_ids":["p01"],"status":"covered","reason":"本页给出依据、推导和限制"}
  ]
}
```

`status`可为`covered`、`unanswered`或`omitted`。后两种必须说明原因，不能填已覆盖；`covered`必须引用真实页面编号。需要保留的旧内容可作为有明确出处的独立requirement。每个requirement只对应一项coverage，多页放在同一个page_ids数组。

成稿后、正式交付前执行只读预检：

```sh
node scripts/检查呈现.cjs --report /项目/报告.json --checklist /项目/成稿核对.json
```

输出JSON，退出码1表示核对文件结构、页面引用或报告结构无效；退出码0只表示机械检查完成。`needs_review`保留连续表格、图片阅读和未回答项的提示。此命令不构建、覆盖或批准报告，不能替代统一构建/验收。

预检保守地提示连续含表格的页面，不声称能从配置判断图表实际占比。结构化非visual模式会自动分页，含表格时另提示`table_pagination`：逻辑页少不代表实体页没有连续表格，须在构建后检查实际阅读页。兼容图旁有表格或图片，也不免除对应人工检查。

独立审校者回原问题核对清单是否漏项，再逐页查引用位置是否真正回答，不只看`covered`标签。记录桌面/手机/PDF实际效果，区分软件正常、内容覆盖、事实核验与业务批准。条件没变时不重复核验；改过源配置后重新构建并核对最终截图版本。

有旧稿时，对照同一问题的实际页面，分别记录保留了什么、纠正了什么、读者少读了哪些文字便能看出什么。三分之二是必须满足的底线，但不单凭数量、图形类名或页数证明更专业。代表页审校与完整报告审校分开；视觉方向待确认时不安装候选版本，也不声称整稿已优于旧稿。
