# 历史回归与迁移

## 运行

```bash
node scripts/迁移研究数据.cjs --input legacy.json --out ../回归结果/本轮迁移
node scripts/回归历史样本.cjs --input legacy.json --out ../回归结果/本轮回归
```

输入为旧版报告配置，输出必须是新的独立目录。不能使用原资料目录及其子目录、Skill 包目录或含软链接的路径，不支持覆盖。真实客户资料只能落在项目根目录的 `回归结果/`，不能放入包内的测试样本、文档或安装目录。匿名测试用系统临时目录，结束后自动清理。

默认模式为 `preserve`，推荐用于旧报告交付。生成四份文件：

- `报告.json`：直接保存原输入字节，不改字段、格式、原图配置或正文。副标题、块标题、布局、备注、来源和附件声明全部保留。
- `研究数据.json`：未复核的结构化研究草稿，不把历史结论当作当前事实。
- `结构化分析报告.json`：原迁移器生成的低保真结构报告，仅作分析底稿，不替代原报告。
- `迁移缺口.json`：完整 `legacy_snapshot`、原有证据缺口及新增 `delivery_fidelity` 保真摘要。

本地图片 `pages[].blocks[].file` 和获准 PDF `attachments[].file` 按原相对路径复制，字节与原件相同。同一路径不同引用只复制一次；引用写法不改。PDF 必须明确 `shareApproved: true` 和非空 `shareBasis`。越界、符号链接、非普通文件、文件缺失、类型伪装、未获准附件以及资产与四份输出文件的路径碰撞都会失败，不能静默排除。回归还保留 `回归结果.json` 和 `交付/`，资产不得占用。

所有文件先写入独立临时目录，回读报告与资产哈希、复核原件未变后，才整体重命名为输出目录。失败只清理本次临时目录，不覆盖原件或他人的输出。

回归另外生成 `回归结果.json`，通过新版主入口构建到 `交付/`，随后调用主验收接口。工具不联网、不重新访问来源，不调用旧安装包运行时；原版兼容引擎随新版包提供。环境变量 `ANQIAN_OLD_SKILL_ROOT` 只供测试原样本基线使用，产品脚本不依赖它。

导出接口：

- `migrateLegacy(legacy) -> {research, report, gaps}`：保留原内存分析 API，不读本地资产、不修改参数；返回的 `report` 不是保真交付。
- `migrateFile({input, out, mode:'preserve'})`：默认原文保真，返回原报告 `report`、独立 `analysisReport`、研究草稿与缺口。
- `runRegression({input, out})`：结构化校验只针对 `research` 与 `analysisReport`；交付调用 `buildReport({researchPath:'研究数据.json', reportPath:'报告.json', outputDir:'交付', overwrite:false})`，再调用 `acceptReport(交付目录)`。

只有明确指定 `--mode structured` 才保留旧低保真行为：生成三份 JSON，`报告.json` 为结构化分析结果，复杂图可能转表，图片与附件仅在快照留档，不读取或复制。此模式不代表保真迁移。

```bash
node scripts/迁移研究数据.cjs --input legacy.json --out ../回归结果/仅分析 --mode structured
```

## 分析与保真分开

以下映射规则只描述 `研究数据.json` 和 `结构化分析报告.json`，不能用于解释保真交付的原图数量。`迁移缺口.json` 的 `issues_scope` 为 `structured_analysis`；原有 `facts.mapped_charts`、`table_fallback_charts`、`archived_only_charts` 与资产排除警告仍忠实保留，但仅指分析底稿。

保真结果单独看 `delivery_fidelity`：包含原报告 SHA-256、原图数与保留图数（例如“6图仍6图”）、全文保留说明，以及资产路径、字节数、哈希与引用清单。这里证明配置与资产保留，不等于实际图形已经通过浏览器或人工检查。

原项目、来源、页面和图表编号不重排。报告日期、访问日期、发布日期、统计期及原限制保持原样；缺失值写“未披露”，不取当前时间。完整历史配置保存在私有输出的 `迁移缺口.json` 的 `legacy_snapshot`，保留全部原文、图表数据和空附件事实。

研究问题编号仅由页面编号派生，明确标为未确认的问题映射。原页面判断转成 `draft` 观点，项目固定 `internal_draft`，页面固定 `research_stage`。不创建已验证的假说、机制、文献对照或计算记录。

只在单一明确来源、原标题或口径能够给出候选类型、无反推/指数化时，将历史图表转录为未复核证据。企业年报候选对应企业披露，明确统计口径对应行业统计；类型仍需人工确认。无法确定类型、多来源逐值归属不明、缺少调查样本量或商品价格时，仅保留原文并警告，不硬套证据类型，不伪造零价格或样本量。

分析底稿将逐页原文、表格和全部图表 JSON 保留在备注与私有快照中。分析正文转录文字、列表和历史判断，并明确标注未复核。单来源、单系列、无推算且类型明确的图表，逐个登记未复核 `evidence.value/unit`，再映射新版 `{type,labels,values,unit,evidence_ids}`。证据与观点的 `claim_type` 使用 `judgment`，不会伪装成已核实事实。

分析底稿对多来源、复合图、反推或相对柱高等不强转：在可读表格中分别转录原系列、项目、绘图值、原始标签和单位/轴名称，不重算、不混同相对柱高与真实量值。逐值来源与计算缺失仍为缺口，表格不自动登记为新证据。分析底稿中的单页多图会转表；原表无法同时使用单一表格槽时，按列名逐行转为正文。这些降级不会进入默认保真的 `报告.json`。

结构化分析页面的 `source_ids` 仅取本页实际结构化证据的全部来源，故事线与分析报告一致；没有证据时为空。`迁移缺口.json` 的 `page_mappings` 单独保存 `original_source_ids`、实际 `evidence_ids`、`evidence_source_ids`、尚无对应证据的旧引用，以及原页未列出但图表证据带入的来源。旧引用也写入分析备注。补齐引用关系不是补证据，不代表旧结论已获支持；保真报告仍保留原引用。

**保存了原图数据不等于重建了原图**。原图数、图形映射数、降级表格图数、原页面配置数和构建后实际页数分别报告，不能冒充原版完整还原或视觉验收通过。

## 规范依据与范围

以 Product-Spec REPLACE-001 至 REPLACE-006 为本轮替代要求。旧版的复杂图形、完整正文、图片和获准附件是保留基线，不能用结构化分析的转表或证据缺口作为删减交付的理由。REQ-008 / AC-023 至 AC-026 的研究审校与技术、内容、业务分层仍有效：原文保真不等于事实核实，不等于旧版替代验收全部完成。

结构化分析的附件数组仍为空；默认保真交付则复制通过路径、文件与明确授权检查的 PDF，保留原批准声明。`attachments_were_empty` 只说明原输入是否为空，不代表保真交付排除了非空附件。工具不会替研究负责人补写批准依据。

重复或非法编号仍拒绝分析，不自动编号掩盖问题。保真输入的安全与构建有效性由保真路径独立校验；结构化分析的缺口不能被改写成已核实证据。

## 验收分层

- 结构通过：仅说明基础字段和关系可被解析。
- `built_not_verified`：构建 API 已返回，仍需浏览器、PDF、图表和人工视觉验收。
- `technical_passed`：主验收接口完成实际离线浏览器、PDF等技术检查；原图人工对照和业务判断不自动通过。
- `not_run`：构建尚未就绪，转换结果与缺口已保存；CLI 非零退出，不能当技术回归通过。
- `blocked` / `failed`：校验阻断或构建失败，具体原因保存在结果中。
- 内容复核固定 `not_reviewed`，业务验收固定 `not_verified`，不会因技术成功自动升级。
- 第二真实项目固定 `not_completed`。即便使用第二份配置运行，也要另行提供资料范围、授权、输入版本与浏览器/PDF/人工证据，才能由主流程认定迁移验收完成。

`technical_acceptance` 单独保存主验收回执，`chart_replay` 保留原图人工复核状态；结束时回读原 JSON 与原资产哈希。回归脚本已自动调用浏览器/PDF主验收，但工具完成不等于所有业务和人工视觉门槛完成。

保真迁移 CLI 不因结构化分析的 fatal 返回失败码；`analysis_fatal` 与 `issues_scope` 单独报告分析问题。保真回归也不因结构化分析的校验失败或缺口 fatal 单独阻断，原始输入的结构、引用和安全由主构建路径检查。只有保真迁移、保真构建或主验收本身失败才判定该路径失败；`structured` 继续保留原分析门禁。

```bash
node --test tests/历史回归.test.cjs tests/保真迁移.test.cjs
RUN_DELIVERY_TESTS=1 node --test tests/历史回归.test.cjs tests/保真迁移.test.cjs
```

实际交付测试复用已配置的 `ANQIAN_NODE_MODULES` 和 `ANQIAN_PYTHON`（默认 `python3`），不安装依赖。原样本基线可由测试环境中的 `ANQIAN_OLD_SKILL_ROOT` 指定；未指定时使用新版包内的同版匿名样本。
