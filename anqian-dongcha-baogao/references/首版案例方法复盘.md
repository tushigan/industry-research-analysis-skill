# 首版案例：匿名方法复盘

本文件仅保留可迁移的方法与脱离原始项目的表达示例，不包含客户名称、客户原文、金额、来源网址、账号数据或第三方 PDF 全文。不得将示例视作任何真实客户事实，也不得据此重建客户报告。

## 可以迁移的做法

- 先完整读取客户材料，再将企业陈述与外部研究分开。客户说法可以帮助确定问题，但不自动成为独立证据。
- 将陌生行业拆成行业机制、竞争渠道、产品体验和消费者需求等方向，随后围绕客户经营问题综合；方向是覆盖检查，不是固定页面目录。
- 先完成逐页判断和图表任务，再制作图表主导的报告。正文、讲解备注与来源使用同一套证据，修订时联动更新。
- 为价格样本记录选中规格和优惠条件；来源引用保留原始页码。报告增删页面不能改变原文定位。
- 单文件报告、资料阅读和讲者功能属于交付能力；选择哪些功能由用户需要决定，不能反过来驱动研究内容。

## 不应迁移的项目细节

不固化原项目的问题数量、页面数量、图表数量、日期、产品判断、价格样本、历史页码映射或渠道选择。不要复制个人路径、云文档地址、段落标识或已绑定客户的同步脚本作为通用默认值。

不把某次客户交流中的判断做成所有食品品牌的定位规则。第二个真实食品项目的迁移效果仍待检验；本 Skill 标记为首版试用，不宣称跨品类和跨行业验证完成。

## 修改前后：方法示例

以下文字是概括后重新编写的示例，不是客户原话或实际结论。

### 从问题清单转为研究回答

修改前：“行业有多大？客户在哪里？下一步做什么？”随后用多数页面展开待确认问题。

修改方法：把问题放进研究底稿。只有当证据能支持回答时，才进入对客故事线，并写明该发现对客户选择的意义。如果目前尚不能回答，交付内部阶段稿及具体缺口，不将问题框架命名为已完成的客户洞察报告。

### 从商品观察转为有边界的判断

修改前：“市场已经形成清晰的消费升级趋势。”依据只有某次商品规格与售价观察。

修改后：“本次商品样本呈现不同的规格与价格组合。”先保留观察边界，再研究这些组合与使用场景的联系；没有消费者证据时不扩展成需求升级结论。

### 从外部案例转为可讨论的启发

修改前：“参照企业采用了某种渠道，客户应当全面复制。”

修改后：“该案例提供了一种渠道组织方式。对客户的适用性取决于供货与合作条件，可先比较双方条件。”外部案例提供机制线索，不替代客户经营验证。

## 首版测试带来的约束

既有基线测试中，未加载本 Skill 的 Agent 多数事实边界判断通过，没有随意编造数据；不能据此声称原有能力全面失败。暴露的问题是：容易把企业事实与缺口、会面待确认问题、定位工作稿排成客户报告主要内容；证据不足时仍可能交付视觉完整的问题框架。

因此首版重点设置“内容是否已有实质回答”的关卡。评估应观察实际研究底稿、观点和对客内容，而非只检查有没有风险提示或是否达到预设页数。证据不足时如实停止是正确结果；形成有根据的有限洞察并完成范围明确的短报告，也是正确结果。

本文件不证明当前 Skill 已安装，不证明工具验收通过，也不替代后续真实项目验证。
