# 报告原型与版式

`0.5.0` 双模式说明。本页描述契约与检查要求，实际替代验收以当次完整回执为准，不声明业务验收通过。

## 模式与公共入口

主构建入口按配置识别输入，不将两种契约混用：

- 原版保真配置含 `id,sources,charts,pages,attachments`，页面内容在 `blocks` 中。用包内兼容引擎保留原表达，不要求改造成结构化证据。
- 结构化配置使用研究编号及独立的 `研究数据.json`，继续按schema、证据、来源和逐值数字校验；下文的结构化渲染协议只适用于此模式。

`build(project, overwrite=false)` 读取项目中的 `报告.json`，输出到项目的 `交付/`。
高级 `buildReport({reportPath,outputDir,researchPath?,overwrite?})` 对原版可省略 `researchPath`；结构化输入必须提供。
原版附带研究文件只作为 `结构化研究底稿.json` 保存，不使原版图表自动获得证据批准。
外部调用应使用 `scripts/构建报告.cjs` 和 `scripts/验收报告.cjs`，不直接调用内部兼容引擎绕过安全与事务包装。

## 原版保真

`scripts/兼容引擎/` 与 `assets/兼容模板/` 随包提供，复用 `assets/依赖/`，无运行时外部旧版依赖。
原始 `charts[].option` 经数据与安全检查后保留原ECharts配置，不转表、不重写轴线与系列，也不因为改用新版入口重排原页。

- 图形包括柱图、折线、饼图和散点；支持堆叠、柱线双轴、横向柱图及同页多图。
- `blocks` 保留 `text,list,chart,image,table` 及其原始顺序，支持图/文/表/图片混排；布局保留 `single,two-one,two-equal,three`。
- 原标题、副标题、图表标题、正文、`takeaway,notes,sourceNote,citations` 和来源定位完整保留。原版一页对应一张横版主页面，不自动套用visual精简索引或结构化续页规则。
- 原图按项目内PNG/JPEG/WebP读取并内嵌，检查路径、文件头与扩展名；获准PDF保留引用页、跳页、缩放、适宽、新窗口及下载功能。
- `presenter` 明确控制独立讲者台。主窗口和讲者窗口双向翻页，保留当前页/下一页预览、备注、计时、拖动缩放、布局保存及恢复；关闭讲者时不能用URL参数重新启用。
- 输出 `研究数据.json` 是原报告配置副本，不是已验证的结构化研究。旧清单字段保留，统一包装另加兼容模式、输入/资产/构建器/成品指纹与验收状态。

仅接受安全的JSON数据配置，不允许函数、可执行脚本、原型污染字段、任意CSS、外部图像加载、路径逃逸或未经授权的PDF。
HTTP(S)来源与原文链接用于主动定位，不代表允许页面自动联网加载资源。标题与文本按文本转义，不执行内含HTML/script字符串。
原版保真不等于研究事实核验：原日期、口径、限制和缺口保持历史状态，不自动成为当前事实或业务批准。

原版浏览器协议保持 `.page[data-page-id]`、`window.reportReady`、`window.REPORT_DATA`、`window.PAGE_NOTES` 和从0开始的 `window.go(index)`。
讲者用 `?presenter=1`，嵌入预览用 `?embed=1&page=...`；资料阅读器使用 `#reference-dialog`。
这与结构化模式的 `.report-page`、`window.__report` 和 `#presenter` 不是同一协议，浏览器/PDF验收必须按模式分流。

## 兼容模式的新稿关系图

新研究或内容修订可使用 `diagram` 块，以真实文字表达步骤、任务比较或机会成立条件；不用虚构数值画柱图，也不将分析文字截图作为图形。历史保真输入未使用此块时，保持原来的布局与样式。完整新稿至少三分之二物理页须以实质图表为主，按[图表占比验收](图表占比验收.md)实际复核；本节组件合规不等于图表主导页合格，文字化的comparison或steps仍可能不计入。

图形页必须为 `layout: "single"`，`blocks` 仅放一个图形块。标题、副标题、判断、出处与备注仍使用既有页面字段，不往图形内塞脚本或任意样式。例如：

```json
{
  "type": "diagram",
  "variant": "opportunities",
  "title": "需要成立的条件",
  "columns": ["方向", "成立条件", "风险"],
  "rows": [["小规格试销", "先确认产线与渠道接受度", "单件包材成本可能上升"]]
}
```

- `steps`：2–3列，最多5项，按行顺序表达确有先后关系的步骤。
- `comparison`：3–4列，最多3项，横向比较同一任务下的条件或选择，不声称因果。
- `opportunities`：恰好3列，最多6项，每项为方向、成立条件、风险。5–6项时桌面及PDF为三列两行，手机纵向重排。不要为填满版式而捏造方向。
- `control-chain`：显式选择的控制链，恰好四列 `['环节','控制动作','守住的结果','失控后果']`，3–5行；沿用 `single` 单块页。按行顺序显示流程节点，动作向下连接守住的结果，失控后果通过独立红色虚线分支连接，不将失败后果串成必然发生的步骤。桌面/PDF横排，390px手机纵排；所有关键文字至少14px。只在选择此variant时追加 `控制链图形.css`，旧三种图形及公共CSS不变。
- 控制链环节名最多18字，其余每格最多32字，最多2个手动行；另按实际节点数估算印刷宽度：环节最多2个显示行、动作/结果/后果最多3个显示行。超出时缩短说明或拆页，不压字号。箭头表达作者输入的控制逻辑，不是自动验证的实证因果；证据性质与关键限制仍写入页面副标题、判断、出处和备注。
- 可选 `title` 最多48字、单行；列名最多12字、单行且不重复；首列最多24字。其余单元格：`steps`及1–4项机会图最多60字、2个手动行；`comparison`最多48字、1个手动行；5–6项机会图最多40字、2个手动行。
- 字数上限不保证一定放得下。构建前同时估算印刷换行，超容量会报错；应精简重复说明或拆分论点，不能压小字号或裁掉条件。详细依据放备注，但正文须保留关键推导与限制。

文字直接保存在HTML中，关系图正文与条件字段最小14px。仍须实际检查桌面、390px手机及PDF：技术容量检查不能替代逐页可读性与语义审校。成稿前后的内容保留要求见 `成稿与保留检查.md`。

控制链块示例（从中保30页修订稿第22–23页压缩的待验证框架，不是企业实测结果；页面保留该性质及原有出处）：

```json
{
  "type": "diagram",
  "variant": "control-chain",
  "columns": ["环节", "控制动作", "守住的结果", "失控后果"],
  "rows": [
    ["原料与生产", "核进料、卫生、烘烤与冷却记录", "批次稳定与产品放行", "批次漂移、返工或退货"],
    ["配方与包装", "核水分活度、阻隔密封及分时点品质", "包装适配与品质接受终点", "运输后品质不稳"],
    ["储运与终端", "核储运条件、批次日期与先进先出", "可售区域与剩余销售窗口", "临期折损抵消毛利"]
  ]
}
```

### 关系分支图（未安装候选新增）

`variant: "relationship-map"` 用于有明确汇合、分支或条件连接的内容。不是自动把表格连上线：先说明连接性质及核心判断，再写图。统计数据仍优先用真实统计图，详细核查表不强制转图。

此块只接受 `type,variant,title,columns,edges`，仍为 `single` 单块页。`columns`恰好三列，每列 `{title,nodes}`，每列1至4个节点；节点 `{id,label,detail}`，编号全图唯一且只用小写字母开头的字母数字、连字符及下划线。标题最多48字，列名16字，节点名18字；正文最多72字（四节点列最多42字），另按印刷行数检查，过密直接拒绝。

`edges`为2至16项 `{from,to,kind}`，只连相邻下一列，不允许孤立节点、重复边、反向或跨列线。`kind`为`inference`（研究推导）、`condition`（待核条件）、`reject`（限制或失效分支），不能用线条暗示未经证明的因果。图中文字须说明汇合需要全部还是任选、失效条件是什么，不能只靠颜色。

桌面/PDF保留真实曲线连接、可选择的HTML文字与矢量线条；窄屏按列重排并逐条列出连接两端及性质，不缩小文字伪装可读。只选择此variant才加入专用样式，旧输入不变。样例见`tests/关系图.test.cjs`；图形存在不等于符合三分之二要求，仍须实际审校。

## 迁移选择

`node scripts/迁移研究数据.cjs --input /原资料/报告.json --out /新的独立项目` 默认 `preserve`：
原报告JSON逐字节保留为 `报告.json`，图片和获准PDF按原相对路径复制；另存 `研究数据.json`、`结构化分析报告.json`、`迁移缺口.json`。
原版交付使用原 `报告.json`，不能误将分析报告当作等价替代。迁移目录中的研究底稿与交付目录中的原配置副本含义不同。

显式加 `--mode structured` 只输出结构化分析契约，不复制原本地资产；可能有图形、正文和资产保真缺口，须读缺口后补证与重排。
两种迁移都保留原件，不覆盖已有输出，不伪造缺失值，也不批准历史事实或业务用途。

## 结构化输入与责任

`renderReport({research, report, fingerprint, assets, attachments})` 返回完整 HTML 字符串。
可选 `onRendered(data)` 回调在返回前提供完整实体页元数据；构建器可传入 `onRendered: data => { metadata = data; }`，不必更换字符串返回接口。
`renderReportDocument(...)` 使用相同输入，返回 `{html,pages,pageCount,titles,fingerprint,notebookHTML}`；visual模式的独立底稿HTML也通过onRendered回调提供给构建器。结构化非visual模式的底稿返回值为null，原回调结构不增加字段。
`pages` 为实体页面记录，字段为 `id,logicalId,title,notes,sources,evidence,limitations`；清单及逐页备注应使用此数组，不按 HTML 源码中的 CSS/JS 字符串计数。
本模块只读包内模板，不读取或依赖旧版 Skill，也不读取配置中的图片路径或附件路径。
调用方负责研究校验、路径和图片安全、附件授权、指纹、输出覆盖保护及 PDF 实测。

- `assets.echarts`、`assets.lucide` 为可信的本地静态依赖文本，不接受客户输入脚本。
- `assets.attachmentScript` 不由渲染器插入。构建器统一插入附件 JSON 与阅读器。
- `attachments` 为已安全处理数组。只输出标题、页数和引用页按钮，不序列化二进制数据。
- 按钮接口：`button[data-attachment-id][data-attachment-page]`；阅读器提供 `window.__attachments.open(id,page)`。
- `page.body` 为文字或段落数组；不解析 HTML/Markdown。
- `page.table` 为 `{columns: string[], rows: (string|number|boolean|null)[][]}`，最多 8 列，行列数必须一致。
- `page.image` 原始配置只有 `path,alt`；构建器只读取项目内经文件头核实的 PNG/JPEG/WebP，安全预处理后添加 `data_uri`。WebP同时核实RIFF长度和图像数据块边界，拒绝GIF、SVG与外链。图片是否能真实解码仍由浏览器验收检查。
- `page.statistic` 必填 `value,unit,label,evidence_ids`，可附 `question,sample_size,population,period,limitations`。
- `page.fact_nature` 可为 `client_statement,external_fact,research_judgment,working_hypothesis,recommendation`；未指定时按观点 `claim_type` 的 `fact,client_statement,judgment,hypothesis,recommendation` 分别显示外部事实、客户陈述、研究判断、工作假设、建议。旧数据缺少类型时回退为研究判断。
- 观点为 `draft` 或页面为 `research_stage` 时只附加“（草稿）”，不改变内容性质；显式性质与观点类型是否一致由研究校验检查。
- 无来源的建议页用 `sourceNote` 明示推导依据；业务合格与否由研究校验模块决定。

## 结构化物理页面

### 视觉提报

横版可配置 `report.presentation_style: "visual"`；未配置时保持历史分页行为。
页面配置 `visual_layout: "comparison" | "steps" | "matrix" | "split" | "charts"`。
前三种复用已校验的 `table.columns/rows`，分别表达并列比较、条件步骤与判断矩阵；
`split` 使用图表或图片与正文解释。不得另塞未经校验的文本或为了图形编造分数。
`charts` 并列显示 `page.charts` 中1–3张图，手机上纵向排列。每张图可有独立 `title`；不得混入会被忽略的 `table/image`。`chart` 与 `charts` 互斥。
数据不适合目标版式、字段缺失或超过容量时明确报错，由作者改写论点；不静默裁切。

每个逻辑页只生成一张主讲页，末尾只保留去重的精简来源索引，常规项目1–2页；来源很多时如实分页，不裁切删除。
每张实体页标记 `data-page-kind="main"` 或 `"appendix"`，后者只代表来源索引及已授权附件入口，进入PDF与讲解备注。
完整来源、证据、观点和推理输出为同目录的`研究底稿.html`，保留完整研究JSON，不进入提报实体页、讲者页数或提报PDF。
正文数字引用跳到来源索引，“详细依据”打开独立底稿的对应位置；底稿可返回提报。两份HTML应一起保留，底稿纳入成品清单及哈希检查。
新提报先做三张代表页，经实际截图和用户确认后扩展；技术通过不等于视觉认可。
代表页显式设置 `delivery_scope: "preview"`，完整稿设置 `"complete"`。完整稿遗漏故事线会阻止构建；预览及既有结构化配置的部分故事线会显示“代表页预览”。这只检查页面覆盖，不证明证据、推导和业务判断完整，仍需原稿对照审校。
精简附录不等于删减正文：商业问题所需的依据、推导、判断、经营含义和限制仍在主讲页完整表达，不能只留下结论，再把全部解释移到底稿。
视觉提报的工具栏在独立区域，正文在下方滚动，翻页与手动滚动同步页码。
验收同时保存包含控件的阅读界面截图和不含控件的完整页面截图，不能只看去掉控件后的画面。
以下自动续页规则只适用于未启用visual的结构化报告及A4，不适用于原版保真布局。

横版尺寸为 1440 × 810 CSS px，打印尺寸 381 × 214.3125 mm，保持 16:9。
A4 页面独立排版，打印使用 210 × 297 mm，不靠浏览器把一条长网页任意截断。
相同研究数据只替换报告配置中的 `page_mode` 即可进入另一轨道，不复制事实。

页面块使用保守字数预算分配空间。正文段落可以拆分，表格按完整行分页，每个分页表格重复表头。
超高单行直接报错，不隐藏或裁切。续页重复标题、事实性质、来源索引和指纹。
标题中的“续”表示一个逻辑页有多个物理页，不是新增观点。
字体、浏览器和极端内容仍可能影响实际尺寸，交付必须再做浏览器溢出检查和真实 PDF 页数核对。

A4 默认生成目录，横版默认不生成；可用 `report.toc` 显式覆盖。
目录自身也可分页，其条目页码根据最终物理页顺序静态计算。
来源日期、统计期、范围、取得方式和分享限制可见；证据显示类型、适用的样本或观察信息和限制。
横版图表使用 230px 图高，证据与来源使用 12px / 18px 的紧凑脚注，不把每个字段拆成单独段落。
单证据标准图表页可在一个横版实体页容纳正文、经营含义、限制及来源；更多证据或长文本仍按实际预算拆页。
报告没有可用图表或产品图时不填装饰图，不生成替代事实。

## 结构化图表安全

单系列沿用 `{type,labels,values,unit,evidence_ids}`，类型为 `bar|line|pie`，可加 `title`。
同单位多系列柱/线把 `values` 替换成 `series`：每项含 `name,type,values,evidence_ids`，最多4个系列；顶层仍保留 `labels,unit,evidence_ids`，逐系列核对原数与单位，不把不同单位强画在同一轴。
散点 `type: "scatter"` 使用逐点 `labels` 和 `values: [[x,y],...]`，`unit/evidence_ids` 对应纵轴，`x_unit/x_evidence_ids` 对应横轴，两轴都要登记可追溯数值。
页面 `chart` 或 `charts` 中的全部图表均经过同一安全、证据与来源检查，不能把第二张图藏在校验之外。
拒绝任意 ECharts 选项、脚本、函数、外链图像和非有限数字。允许负值柱图/折线图，拒绝负值饼图、零总量饼图和合计不为 100% 的百分比饼图。
分类最多 40 个，饼图最多 8 个。更多分类拆成多页或改用表格。
从白名单生成静态 ECharts 配置，使用 SVG renderer，关闭动画和 HTML tooltip；坐标轴保留零基准。
`validateChart(chart)` 返回 `{severity,path,message,fix}[]`，错误严重性为 `fatal`。
证据是否支持数字、分母和范围，交由研究校验及人工审校，不由图形渲染证明。
实现依据：[Apache ECharts SVG 说明](https://apache.github.io/echarts-handbook/en/best-practices/canvas-vs-svg)。

## 结构化验收协议

- `.report-page[data-page-id]` 在返回 HTML 中已存在，不依赖脚本创建。
- 每个物理页有 `h1` 或 `h2`、`.page-number`；图表容器 `.chart` 内应有非空 SVG。
- `window.__report = {pageCount,titles,fingerprint,currentPage,goToPage,openPresenter}`。
- `goToPage(n)` 使用从 1 开始的物理页码；`currentPage` 也从 1 开始。
- `window.__reportReady` 在字体、图片与全部图表完成后为 `true`；失败保留 `false` 并设置 `window.__reportError`。
- 打印媒体隐藏工具栏、讲者台和阅读器窗口，显示所有实体页。
- PDF 的实际页数、标题、矢量图、链接和文字层由构建器的 PDF 验收再次核对。

## 结构化讲者台

`button[title="讲者台"]` 打开同一离线 HTML 的 `#presenter` 独立窗口。
主报告与讲者台通过 BroadcastChannel 和有窗口来源检查的 postMessage 同步，消息按发送者序号去重。
单独打开 `#presenter` 也可使用；多个版本按完整输入指纹隔离，不串页。

- 双窗口翻页：`button[title="上一页"]`、`button[title="下一页"]`。
- 页码输入：报告 `#page-input`；讲者 `#presenter-page`。
- 当前页、备注、来源：`#presenter-preview`、`#presenter-notes`、`#presenter-sources`。
- 计时：`#presenter-timer`，按钮标题为“开始计时”“暂停计时”“重置计时”。
- 面板 `#panel-preview,#panel-notes,#panel-sources`；拖拽 `.panel-handle`，右下角 `.resize-handle` 改大小。
- 布局按相对位置保存在 localStorage；窗口变小时限制在可见范围内；窄屏改为纵向排列，并重新计算完整预览页缩放，不覆盖桌面保存布局。
- `button[title="恢复默认布局"]` 恢复默认。浏览器禁用 localStorage 时当次交互仍可用，但不承诺跨次恢复。
- 来源仅 HTTP(S) 地址可打开；本地文件标识及其他协议只作文字，不执行。

## 验证边界

PDF 版式指标采用浏览器记录的正文区域，排除页眉页脚；文字覆盖率计算实际文字矩形的
合并面积，不计算横跨大片空白的外接矩形。缺少区域数据时标记估计值并要求人工核对。
低密度仅产生人工复核提示，线框与装饰不证明有信息图；空正文主讲页会阻止验收。

结构化测试范围包括五种观点性质及草稿状态、静态契约、恶意输入、表格拆页、离线SVG、双向同步、计时、布局恢复及移动/打印媒体；横版和A4均需检查桌面→手机→桌面切换后的预览边界。
原版保真另核对原配置和完整正文，实测图形、原图、PDF附件及讲者台，不用结构化测试代替；具体通过情况以当次回执为准。
运行浏览器测试需 Playwright；无运行时会明确跳过，不计为通过。
浏览器可通过 `ANQIAN_NODE_MODULES` 指定依赖目录；`RENDER_ARTIFACT_DIR` 可保存验收截图。
独立审查、真实客户事实确认和 PDF 成品验证由主 Agent 汇总，不用此模块的单测替代。
