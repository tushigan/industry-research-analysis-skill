# 交付与验收

研究内容和逐页故事线成立后读取本文件。默认采用单文件HTML及同版PDF，是否使用讲者和内嵌资料取决于当前交付约定。一般格式转换不应改造定稿来适配本模板，直接使用相应导出工具。

## 运行环境

构建使用Node.js，不访问网络；ECharts、Lucide和PDF.js随Skill提供，许可证在`assets/依赖/`。浏览器验收需要Playwright与已安装Chromium，PDF检查需要Python的PyMuPDF。

优先读取当前环境提供的运行时信息，并实际确认路径。脚本支持正常安装的Node依赖，也支持环境变量`ANQIAN_NODE_MODULES`指向当前可用的`node_modules`目录；不猜测其他Agent的目录，不为此修改全局配置。必要时取得用户授权后安装缺失依赖。无浏览器权限时按当前环境的审批方式执行，不绕过访问限制。

将当前加载的Skill绝对目录记为`SKILL_ROOT`，新建独立项目目录记为`PROJECT`。以下变量由本次真实路径设置，不原样输入示意路径：

```bash
node "$SKILL_ROOT/scripts/构建报告.cjs" "$PROJECT"
node "$SKILL_ROOT/scripts/验收报告.cjs" "$PROJECT"
python3 "$SKILL_ROOT/scripts/检查PDF.py" "$PROJECT"
```

已有成品需要更新时，先确认这些文件属于当前任务，再向前两个命令传`--overwrite`。保留其他用户文件，不将覆盖参数当作默认许可。

## 项目输入

项目根目录放`报告.json`、实际商品图片和获准内嵌的PDF。构建器只读取项目内的普通文件，不跟随指向项目外的软链接。

`报告.json`使用JSON，不包含可执行JS或任意HTML。以下是字段契约，不是固定研究大纲：

|字段|要求|
|`id`|字母开头，之后字母数字下划线或连字符；不同项目使用不同稳定编号，避免讲者同步串报告|
|`title`、`publisher`|当前报告标题和实际发布者；不能自动沿用案例客户或橙皮书作者|
|`date`|有效`YYYY-MM-DD`，表示当前研究版本日期|
|`presenter`|明确`true`或`false`|
|`sources`|来源数组；每项`id,title,publisher,url,accessedAt,period,scope`；可选`publishedAt`；日期有效，URL为HTTP/HTTPS且不含凭据|
|`charts`|图表数组；每项`id,sourceIds,unit,period,scope,option`；`option`为纯JSON的ECharts配置|
|`pages`|按实际顺序排列的页面数组，至少1页；字段见下|
|`attachments`|附件数组，无附件使用`[]`；字段见下|

来源编号、图表编号和页面编号分别唯一。来源台账中的样本、原文位置和计算字段可附加保存，工具不会代替人工证据判断。来源URL并不证明已读原文。

构建器为图表DOM编号添加独立前缀，配置中的图表编号无需避让页面工具编号。成品清单保存配置与所引用图片、附件的输入指纹；资料修改后必须重新构建，不能用旧成品通过验收。

### 页面

每页填写`id,section,title,subtitle,layout,blocks,takeaway,notes,sourceIds,sourceNote`。

- `title`是该页的判断，不是长段结论；`takeaway`说明对客户的含义；`notes`为完整讲解文字，不能缺失。
- `layout`为`single`、`two-one`、`two-equal`、`three`之一；不要在一个固定页面塞过多内容。由真实渲染决定是否拆页。
- `sourceIds`关联来源；无外部统计的建议页可为空，但在`sourceNote`注明推导所依据的研究页或会议，不编造外部来源。
- `citations`可选，形如`[{"sourceId":"source-a","page":8}]`，指向已内嵌来源的PDF第8页；不要用报告自身页号替换。省略时按`sourceIds`生成来源链接。
- 不内嵌PDF而希望定位网络PDF页码时，将来源URL设为包含`#page=8`的实际PDF链接，说明这是外部访问。

`blocks`内容块支持：

|`type`|字段与用途|
|`text`|可选`title`，必填`text`；换行可用`\n`|
|`list`|可选`title`，`items`字符串数组；用于有依据的机制或条件比较|
|`chart`|`chartId`关联图表，`title`描述图表；同一图表编号只渲染一次，跨页复用需独立编号|
|`image`|`file`项目内相对路径，`alt`，`caption`注明来源；PNG/JPEG/WebP；产品图须真实且与文字对应|
|`table`|可选`title`，`headers`，二维`rows`，列数一致|

统计图支持柱状、折线、饼图和散点（`bar,line,pie,scatter`）。每个series使用显式数字`data`；可用`{value:数字,name:类别}`，散点可用数字坐标数组。首版不支持函数formatter、dataset或任意脚本，避免不可移植的执行代码。其他图式可用定性表格表达，或按任务需要另行扩展后验收，不强行替换成不合适的图。

ECharts的`option`决定坐标轴、图例、标签、系列和网格。优先从测试样本的结构出发，替换成已核数据，不复用其合成数字。柱形图通常从0起点，饼图仅用于完整且互斥的整体构成；多选调查不要画成总和100%的饼图。技术校验通过不等于统计表达正确。

### PDF附件

每项填写：`id,sourceKey,title,file,pages,citedPage,formatLabel,description,shareApproved,shareBasis`。

- `sourceKey`对应来源编号，不必与附件`id`相同；同一来源编号只关联一份PDF。不同文件分别建来源。
- `pages`是真实文件页数，`citedPage`为主要引用页。构建检查范围，浏览器及PDF检查再核真实页数。
- `formatLabel`准确写“完整研究报告”“年报摘要”“节选”等，不能把摘要称为全文。
- `shareApproved`必须为`true`，`shareBasis`记录当前分享范围的许可依据。公开下载不等于取得对外分发授权；不明确时不嵌入，只保留来源链接。
- 不随Skill分发客户逐字稿、账号截图或第三方研究全文。只有当前项目明确需要且获准分享时才加入该项目交付。

内嵌会增大HTML文件。按需要保留资料，并在交付时说明体积和发送渠道限制；不擅自删减用户要求保留的完整资料。

## 成品与版本

构建生成`交付/案前洞察.html`、`逐页讲解备注.md`、`成品清单.json`和`研究数据.json`。其中后两项用于内部核查，研究数据可能含内部分享依据，不默认作为对客附件。

验收脚本生成`交付/案前洞察.pdf`以及`验收/`中的截图和结果。HTML、PDF和备注为同一配置生成。最终变更后重新构建和验收；文件哈希变化意味着此前截图和云端附件不再证明当前版本。

单HTML离线提供正文、图表、图片、讲者功能及已嵌入PDF；外部网页仍需联网，飞书等受权限控制。PDF阅读版保留来源网络链接，不自动将所有参考PDF追加进报告正文。

需要工作包时，只打包当前成品、可分享资料与交接底稿；排除账号信息、临时日志、未采用客户资料和验收缓存。核对包内成品与当前交付逐文件一致。

## 真实验收

1. 数字、单位、时间、样本、原始页码及推导人工审校；图表值与台账复算。
2. 运行浏览器验收，检查桌面与手机布局、图表与图片、实际翻页、讲者同步、计时与布局保存重置；目视检查截图，不能只看自动结果。
3. 启用附件时测试空目录离线单HTML，引用跳页、首尾页、翻页、缩放及下载一致性；扫描PDF可以无文字层，不能因此伪造可选文字能力。
4. 检查PDF真实物理页数、逐页标题、可选文字、矢量内容、链接和截图；不要交付整页位图拼成的PDF。
5. 若选择飞书或其他云端同步，通过当前可用能力读取目标，确认范围后写入；图片紧随对应文字，上传后回读并下载核版本。不能直接套用案例文档编号。授权不明、上传结果不明时停止该写入并核查，不盲目重传。

测试工具检查的是技术与结构，不替代研究结论的专业审校。验收未完成时明示具体状态；不能因为生成了文件就称完整交付。

## 首版回归测试

```bash
node --test "$SKILL_ROOT/scripts/构建测试.cjs"
node "$SKILL_ROOT/scripts/测试样本.cjs" "$PROJECT"
```

第二条只用于新建技术测试目录，会生成明确标注的合成数据，不可在真实项目目录执行。附件测试可在另一空目录执行`node "$SKILL_ROOT/scripts/制作附件测试.cjs" "$PROJECT"`，需`pdf-lib`；生成的3页PDF由脚本自制，不涉及第三方研究内容。然后执行构建、浏览器验收和PDF检查。

正式研究不能使用测试数据。不同品牌名、不同页数的技术回归不等于第二个真实客户项目验证。
