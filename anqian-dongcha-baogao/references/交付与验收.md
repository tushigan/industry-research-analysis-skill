# 交付与验收

新写与内容修订的完整主报告另有硬门槛：[图表占比验收](图表占比验收.md)。按最终全部物理页计，图表主导页至少三分之二；未逐页登记和独立复核、比例不足、方案与最终页序不一致或仅有文字框伪装图表，均不能判成稿完成。技术通过不放行该门槛；统一验收通过`--review`运行比例门禁，单独的`检查图表占比.cjs`用于预先排查。登记/比例通过也不代替图形语义检查。原有内容完整、证据、可读性及业务批准要求同时保留。

新研究与内容修订在统一验收之外执行[成稿与保留检查](成稿与保留检查.md)：问题子项和保留内容逐一定位，运行只读呈现预检，再由独立审校者核对实际答案。预检的`mechanical_passed`不能替代内容或视觉批准；历史保真回放不强制补造研究清单。可重排图形在手机、桌面、PDF检查文字完整、关系可读和关键字不低于14px，不以图形存在代替可读性。

本文对应本地 `0.5.0` 双模式能力。不得把引擎自检、文档更新或生成文件写成替换验收已完成；以实际安装目录及当次回执为准。
当前阅读体验改动为未发布候选。代表页须对照同题旧稿说明阅读改善与信息保留，单独记录视觉审查和用户确认；三页通过不等于完整报告通过，不自动更新已安装入口。

## 四种不同结论

1. 数据检查：结构化模式检查字段、引用、逐值数字、单位和已知规则；原版保真模式检查输入安全、结构及原文/配置/素材保留。后者不冒充结构化证据重新核验，两者都不证明原文正确。
2. 技术验收：当前指纹下，实际浏览器和PDF检查通过。
3. 内容与视觉审校：负责人回到原文复核，实际逐页查看，留下单独记录。
4. 业务批准：负责人明确批准用途与外发；脚本不能代替决定。

统一 `验收报告.cjs` 的技术通过返回 `technical_passed`，内容与视觉仍为 `manual_review`，业务为 `not_granted`。
结构化清单仍为 `draft`、总验收 `blocked`；原版清单保留旧字段，在 `compatibility` 中记录技术状态、指纹和人工审校要求。
原版内容检查为 `legacy_structure_only`、证据为 `not_revalidated`。技术通过不改变历史数据、原日期、证据事实或业务批准状态。

## 按模式验收

- 原版保真：自带兼容引擎，不调用旧安装包。纯转换或历史回放明确声明`production_mode`，逐页核对原标题/副标题、正文与blocks顺序、图表配置/标题、takeaway、notes、citations、原布局、原图与获准附件；检查堆叠、柱线双轴、横向柱图、散点、多图及混排未被转表、删改或重排。兼容输入用于新写或内容修订时，同样必须提供结构化研究底稿、逐页方案和最终登记。
- 结构化研究：继续严格证据校验；visual保留完整正文论点、依据、经营含义和限制，末尾来源索引精简，详细证据与推理在完整独立底稿。代表页不冒充完整报告，精简附录不能用删除正文实现。
- 两种模式共用主构建和验收入口，浏览器协议、分页与PDF检查按模式分流，不能用一种模式的选择器、清单或页数假设验收另一种。

原项目目录命令保持，但构建必须补明确用途，例如历史回放使用 `node scripts/构建报告.cjs /项目 --production historical_replay`；不能用输入格式猜用途。
主验收也接受交付目录；Python项目目录入口进入统一浏览器/PDF及指纹验收，不直接覆写已登记回执。
高级 `buildReport` 对原版配置可省略 `researchPath`，不要求为了构建旧报告伪造研究底稿；结构化输入仍必须有研究数据。

## 实际检查

- 断网Chromium等待字体、SVG图表、图片加载，检查桌面、手机及打印视口。
- 检查文字越界、空图、图片失效、水平溢出，逐页截图。
- 打开对应模式的独立讲者台，双向翻页、备注、预览、计时暂停、拖动缩放、重载恢复、布局重置及窗口边界；禁用讲者也需检查参数不能绕过。不能只验证按钮存在。
- 内嵌PDF实际渲染，检查非空画布、首尾页、引用定位、直接跳页、快速翻页、缩放/适宽、新窗口页码、下载字节/哈希及手机阅读器边界。关闭附件后报告页码保持不变。
- PDF实际页数、标题顺序、纸张比例、文字层、矢量路径及来源链接由PyMuPDF检查。
- 结构化A4目录按实体分页计算，再核对真实PDF内部跳转目标，不按逻辑页数猜页码；原版按原始页面顺序、标题、判断及来源检查。
- 空页和越界失败，稀疏页提示人工复核，不把几何比例当作审美判断。
- 输入、图片、附件、模板、依赖、构建器和成品指纹不一致时拒绝验收。

### 客户表达检查

结构化报告的 `audience_mode` 缺省为 `client`。明确设为 `internal` 的产物仅供内部研究或技术回归，
成品清单必须保留用途标记，且 PDF 导出入口直接阻断；不得把内部 HTML 或研究底稿交作客户成品。
内部产物改为客户模式后必须重新构建并执行全部表达扫描。

交付前检查客户可见的标题、副标题、正文、图表标签、表格、来源说明、讲者台及兼容模式原始备注。
研究底稿可以保留内部审计语言，但客户成稿不得出现“仅核对本地摘录”“外链未复核”“本次未执行”
“研究缺口尚未补齐”“现有资料不能给出市场规模”“上版完整页面”等内部过程描述。
命中时按 `fatal` 处理：阻断所有会生成客户可见成品的结构化报告及原版保真构建。`internal_draft`、`client_discussion`、`formal_delivery` 与 `delivery_scope: preview/complete` 均不能豁免；它们描述研究阶段或正文覆盖，不是把内部过程话术放入成品的许可。纯内部研究底稿可保留审计说明，但必须与 HTML、PDF、讲者台及逐页讲解备注分开；
项目目录生成 `成稿表达反馈.json`，反馈页码、字段、命中原句、必要上下文、问题和建议方向。
不能通过把问题改放到 `sourceNote`、`notes`、图表标签或讲者台来绕过。反馈须单独交给用户，说明待补资料或待确认口径，不得把反馈转写成成品免责声明。真实业务边界表达不应仅因含
“不能”“尚未”等字样被误拦，须区分业务事实与内部工作状态。

## 输出保护

下列规则由公共入口的安全和事务包装负责；包内兼容引擎是内部实现，不作为绕过保护的用户入口。

默认拒绝已有目录。显式--overwrite只允许替换已知且未手改的产物，旧目录保留为相邻备份。
构建失败不替换已有成品，PDF检查成功后才替换旧PDF。
首次PDF导出遇到未登记的同名文件直接拒绝，不覆盖用户文件。交付目录及验收子目录
含符号链接、硬链接或特殊文件时拒绝读写验收，不能借链接写到目录外。
重新验收先让旧技术通过状态失效，再写当次回执，不能失败后沿用旧通过。
备注使用实际物理分页后的顺序。报告配置和证据应回源修改，再重建，不手改HTML/PDF。

## 分享和历史

内嵌PDF需登记批准、依据、真实页数、引用页和格式；只有项目内PNG/JPEG/WebP图片和PDF可以读取。
真实路径逃逸与预置data URI被拒绝。批准字段一致不代表授权人一定有分享权，仍需负责人确认。
默认迁移为 `preserve`，原 `报告.json`、图片和获准PDF保留，结构化分析另存；`--mode structured` 只供结构化分析，不承诺原图、正文或资产保真。
历史回归只说明迁移、构建与技术回放，缺假设或计算依据仍保留，不自动重新批准事实、证据或外发用途。
第二真实食品项目没有实际输入及验收证据时写“未完成”，不能用匿名样本替代。

## 替换门槛

替换前须有旧命令、两份真实食品报告及图文附件样本的保真对照、桌面/手机/PDF实测、完整回归和独立复审记录。
客户名称、真实资料与实测细节只留在项目回归记录，不进入公开包。未完成项如实列出，不沿用旧轮次结果冒充本轮通过。
满足门槛并获准替换后，将原包备份到所有客户端技能发现路径之外，稳定旧入口与v2入口使用同一套实现，并分别从实际安装位置构建和验收。
文件复制、客户端发现、技术验收和业务批准分开记录；备份位置与恢复路径须可核对。操作细节见 `安装与MCP配置.md`。
