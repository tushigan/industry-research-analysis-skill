# 机制与既有研究对照

工作假设是可以被推翻的暂时解释，不是先定结论再找资料。
本规范实现产品需求中的研究方法，不声称任何外部理论已经被当前项目证实。

## 假说卡

填写 `statement`、`falsifier`、`question_ids`、`supporting_evidence_ids`、`counter_evidence_ids`、`competing_mechanism_ids`、`next_discriminating_evidence`、`analysis_level`、`status`。

1. 用一句话说判断，并在对客文字中标明“工作假设”或“待验证”。
2. 写清什么可观察结果会使自己放弃或缩小判断，不能只写“需要更多研究”。
3. 列出至少两个解释同一现象的候选机制，区分它们预测的不同结果。
4. 分别登记支持、反例与尚无法区分的证据；同一编号不在没有解释时同时记作支持和反例。
5. 下一步证据必须能区分候选解释，例如同规格同优惠条件重复观察，而非笼统“继续调研”。

没有找到反例，可以保持空数组并产生警告，不能把未找到写成反例不存在。
`draft`、`evidence_indistinguishable`、`ready_for_review` 不等于 `client_ready`。
“证据无法区分”是有效研究结果，不强迫挑出一个胜出机制。

## 机制卡

填写 `name`、`object`、`derivation`、`supporting_evidence_ids`、`alternative_explanations`、`boundaries`、`client_implication` 和 `analysis_level`。
区分“观察到了什么”和“为什么可能发生”：原料、工厂、供应链名词本身不是机制解释。
机制应能说明条件、过程、结果及失败情形，而不是把结果换一种说法。
没有替代解释时，内部阶段产生警告；用于可对客观点或假说时阻断。

## 分析层次

建议使用稳定名称：`task`（任务）、`role`（岗位）、`organization`（组织）、`market`（市场）；必要时明确项目自定义层次。
假说和参与竞争的机制必须解释同一层次的对象。
一次购买任务上的观察，不能直接推出整个市场规律；个人访谈不能直接推出组织制度效果。
跨层次研究保留为既有研究对照，说明推导限制，不通过改标签伪装成同层比较。

## 既有研究对照

每条对照登记 `literature_id`、`framework`、`source_id`、`relation`、`comparison_level`、`limitations`。
补充当前证据 `evidence_ids`、原研究层次 `source_level`、当前层次 `current_level`、差异说明 `level_difference`、可区分性 `discrimination`。

- `confirm`：在明确对象与边界下与既有解释相符，不等于普遍证明。
- `revise`：指出哪项条件、范围或推导需要修改，不能只有“本研究更全面”。
- `missing_dimension`：说明原框架未覆盖什么变量，以及当前证据是否真的涉及该变量。
- `not_comparable`：对象、层次或方法不同，不能作直接验证；可以保留背景作用与限制。

跨层次直接比较而未写 `level_difference` 是 fatal，即使仍为研究草稿，也不能保留成没有说明的直接结论。
缺当前证据、双方层次或可区分说明：内部阶段 warning，对客阶段 fatal。
原文不可获得时登记缺口，不靠搜索摘要转述出“理论已证明”。

## 进入对客状态

对客假说、机制、观点必须有完整分析层次、边界、替代解释及可回查的 reviewed 证据。
相关卡片登记 `content_review: {status: "reviewed", reviewer: "审校人", basis: "审校依据"}`。
这个字段只记录真实发生的审校，不是让 Agent 自填“通过”的快捷方式。
无证据的工作假设可保留内部讨论；不把它升级成可对客结论或无依据建议。
校验器检出结构缺口，不判断任意自然语言推导是否逻辑成立，最终仍须独立审校。
