# 图表占比验收

新写或内容修订的完整主报告，至少三分之二的页面须以实质图表为主。这是必须满足的最低门槛，不是可选建议，也不能单靠它证明报告专业。两种制作模式共用；纯格式转换、历史保真回放不为满足比例擅自改原稿。

## 怎么算

- N是最终交付主报告的全部物理页。封面、目录、来源、结尾、合并进主PDF的附录均计入；只有独立于主报告的研究底稿不计入。用实际渲染/PDF页数，不用可能再次分页的逻辑配置数。HTML与PDF分页不同时分别核算，两者都须过线。
- G是经实际查看、独立复核通过的图表主导页数。每页最多计一次，放三张图不等于三页。
- 合格条件为 `3 * G >= 2 * N`，最低页数为 `ceil(2 * N / 3)`。例如10页至少7页，30页至少20页，33页至少22页。
- 未看、待确认、不可读、关系误导、仅有小配图的页面不计入G；未登记全部页或未独立复核也不能宣布比例验收通过。

## 哪些算

图表是该页主要阅读载体，并让读者直接看出核心判断所依赖的差异或关系，例如同口径数值比较、构成、变化、真实步骤、因果假设、约束路径、结构连接或条件定位。数据图须有单位和口径；机制或假设图须标明未证实的边界。

矩阵只有当维度、交点或位置编码本身承担比较关系时才算。不能编造评分、坐标、面积和优先级，让本来没有依据的判断显得精确。流程节点可以带必要文字，但不能用箭头串起无关段落假装有步骤。

以下不算：纯文字表格、标题加几段话、彩色文字卡片、装饰图标和箭头、产品照片单纯陪衬、长文字截图、非主导的小图。配置里写了`diagram`、`comparison`、`steps`或`visual`不意味着实际页面合格。普通文字表仍可作为剩余页面的必要核查载体。

没有足够数字时，可以用有依据的结构、关系和流程表达；不允许为达标虚构数据。若内容确实不能诚实转为图表，应记录缺口并维持“未达标”，不能自行降低门槛。

## 怎样验收

1. 在`逐页图形方案.json`中先按完整故事线规划，不靠补空页、重复图、缩小字号或删除必要正文提高比例。先运行`检查图表方案.cjs`；预检只核字段、证据编号、预计比例和余量，不生成整稿。
2. 构建后，取得HTML实际物理页序列及PDF页数，绑定报告输入、HTML和PDF指纹。按当前版本查看桌面、手机和PDF；手机可以重排，但必须保留主要关系、关键文字及限制。
3. 在项目内写`图表占比登记.json`，登记每个物理页的编号/页面ID、核心判断、主要图表、合格/不合格/待确认、具体理由和实际截图。没有确切原图，不凭组件数量下结论。
4. 汇总N、G、最低合格页数、实际比例和缺口。由独立审校者复核计入页是否确实以图表承载判断、是否有假关系及重要内容丢失。未登记全部页或未独立复核时标“未通过”，不得用自报合格代替。
5. 比例不足、关键图不可读或内容被削减，回到正文重排；只允许作为明确标注的未达标候选供讨论，不称完成交付。所有改动后重新绑定版本；旧比例不沿用到新版本。

正式流程：

```bash
node scripts/检查图表方案.cjs --plan /项目/逐页图形方案.json --research /项目/研究数据.json --report /项目/报告.json
node scripts/构建报告.cjs --research /项目/研究数据.json --report /项目/报告.json --out /项目/交付 --production content_revision --plan /项目/逐页图形方案.json
node scripts/验收报告.cjs /项目/交付 --review /项目/图表占比登记.json
```

独立排查也可运行：

```bash
node scripts/检查图表占比.cjs --project /项目 --review 图表占比登记.json
```

构建和技术验收后、正式交付前，必须先实际逐页审校，再按[登记格式](图表占比登记格式.md)填写登记并运行此命令。它读取真实HTML页序和PDF页数，校验输入/成品/截图指纹、逐页完整性与双方审校记录；登记无效退出2，比例不足退出1，通过退出0。HTML与PDF分别计算，不接受组件数量代替。

检查器只验证登记与算术，不判断图形语义、不证明审校者身份或截图内容与页面相符；不能虚填肯定记录让机器放行。统一验收已接入该结果，但方案和最终物理页序不一致时，即使比例登记通过也保持阻断，必须按新页序重审。纯转换与历史回放只标记`quality_not_revalidated`，不能作为新制作质量证明。已安装0.5.0尚未同步本候选。
