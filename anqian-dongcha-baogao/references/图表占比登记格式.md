# 图表占比登记格式

这是登记格式和独立排查命令；统一`验收报告.cjs --review`也复用同一检查器执行正式门禁。
它检查登记完整性、文件版本和 `3 * G >= 2 * N`，不识别图形语义、
不验证审校者真实身份，不代替桌面/手机/PDF目视验收，更不代表业务批准。

## 使用

从技能目录运行：

```bash
node scripts/检查图表占比.cjs --project /绝对路径/研究项目 --review 图表占比登记.json
```

`--review` 相对项目根目录解析；也接受项目内的绝对路径。
JSON内全部路径必须相对项目根目录，不得含 `..`、绝对路径或逃逸项目的符号链接。
项目根目录须包含报告原文件、交付文件、登记和截图。
清单优先读取 `交付/成品清单.json`，否则读取根目录的 `成品清单.json`。
建议登记放在项目根目录。新制作报告的统一验收会把当次检查结果写入当前候选交付清单；不会改历史成品或旧候选。

依赖沿用 `scripts/lib/运行依赖.cjs`：
Playwright和其Chromium用于读取实际渲染后的HTML物理页序；
Python的PyMuPDF用于读取PDF实际页数和解码截图。
可通过 `ANQIAN_NODE_MODULES`、`ANQIAN_PYTHON` 指定现有运行时。
缺少依赖或渲染失败也返回未通过JSON，不悄悄跳过。

## 字段约定

- 顶层只接受 `schema_version`、`artifacts`、`html_pages`、`pdf_pages`；版本固定 `"1.0"`。
- `artifacts` 必须有 `report`、`html`、`pdf`，每项为 `{"path":"项目内路径","sha256":"64位小写十六进制"}`。
- 报告还须与构建记录的 `reportPath` 和构建时报告哈希一致；HTML、PDF须与成品清单对应输出一致。
- 支持结构化清单和 `legacy-preserved-v1` 兼容清单；不把逻辑配置数、`page_count` 或 `pages` 当实际分母。
- 不重新计算整个工具包的指纹，因此新增检查器不要求重建全部历史报告。它只检查当前指定报告及相关登记，不证明所有研究输入都已重新验收。
- `html_pages`、`pdf_pages` 各自必须完整覆盖自己的全部物理页，数量可以不同。页码必须是从1起的整数，不能重复或越界。
- HTML记录还必须含实际 `data-page-id` 对应的 `page_id`；PDF只用自身物理页码，不接受HTML页面ID。记录数组不必按页码排序，但页码和HTML页面ID必须匹配实际顺序。
- 每页必须有 `status`、`conclusion`、`reason`、`screenshot`。结论和理由必须是非空文字；不要仅抄组件名。
- `status` 只接受 `qualified`（合格）、`unqualified`（不合格）、`unknown`（待确认）。后两者不计入G。
- 每页截图都必须登记 `path` 和 `sha256`，包括不合格和待确认页；接受能实际解码的PNG/JPEG文件，不接受空文件或只写截图名称。
- `qualified` 页必须同时有 `primary` 和 `independent`。每项含非空的 `reviewer`、`reason`，以及 `verdict`。
- `verdict` 同样只接受上述三种状态；合格页的双方都必须明确登记 `qualified`。
- 双方审校者名称经去首尾空格、Unicode规范化、忽略大小写后必须不同。此检查不证明两个人真实独立，更不能识别同一人的不同别名。
- 不合格和待确认页可省略双方审校记录；若填写，结构和状态仍须合法。双方审校记录针对同页登记的截图及顶层文件版本。
- 所有层级拒绝未知字段，避免拼错字段后被默默忽略。

截图与页面是否真正对应、是否足够清晰、图形是否承担核心判断，仍需人实际查看。
检查器不会比较截图与页面像素，不会认定“填了肯定记录”就完成语义审校。
示例中的合成肯定记录也不能当作真实批准。文件变化后须重做相关人工检查并更新指纹，
不能仅替换哈希、沿用旧截图或旧结论。

## 输出与退出码

- `status: "passed"`，退出0：登记有效，HTML和PDF各自达到比例，仅登记/算术通过。
- `status: "ratio_insufficient"`，退出1：登记有效，但至少一种成品比例不足。
- `status: "invalid_registration"`，退出2：格式、版本、页序、截图、复核记录或运行环境不符合要求；见 `errors`。
- `--help` 输出JSON帮助，退出0。

有效结果包含 `registration_valid: true`，分别输出 `html`、`pdf` 的
`total`、`qualified`、`unqualified`、`unknown`、`minimum`、`shortfall`、
`ratio`（0至1）和 `passed`，以及 `html_page_order`。
未知页不能增加G；33页中21页不通过，22页通过。
无效登记不提供可被误认为有效比例的部分统计。
所有结果声明检查范围，正常检查还明确
`semantic_review: "not_performed"`、`reviewer_identity: "not_verified"`、
`business_approval: "not_granted"`。


```bash
GRAPH_REVIEW_EXAMPLE=1 node --test --test-name-pattern '确切登记JSON示例' tests/图表占比.test.cjs
```

不同依赖版本生成的PDF或截图字节可能不同，以该次输出的真实哈希为准。
