# 行业调研分析

本文对应本地 `0.6.0` 图表规划与交付门禁版。具体安装状态与替代检查结果以当次验收回执为准，不以文档存在代替验收。
生成前方案、完整报告验收与安装分别记录；源码通过不代表客户端安装入口已经更新。
先核对 VERSION.json 与当次验收回执。命令以本文件所在目录为包根目录。
原版保真引擎随包提供，不在运行时调用旧安装包。验收通过并获准替换前保留已安装版本；
替换时先备份到客户端技能发现路径之外，稳定旧入口与v2入口使用同一套实现，详见安装文档。
客户资料、输出及截图必须放在当前项目的独立目录，不写进 Skill 包。

## 任务路由

- 仅格式转换：只读取用户指定的原件并输出指定格式，不启动研究流程，不补写事实，不自动追加研究底稿、HTML、PDF和备注整套成果。优先用对应文档工具转换；现有报告只需PDF时使用原交付的PDF导出命令。缺转换工具时明确说明，不伪造研究JSON来绕过。
- 新研究：先读获准材料并形成问题与证据，不先编报告结论。
- 已有数据：先辨认输入契约。原版配置走保真模式，结构化研究与报告两份 JSON 走严格证据校验；不手改 HTML 中的事实。
- 测试新版：生成匿名技术样本，验证包内两种模式和独立运行；不借用外部旧安装包冒充新版能力。
- 历史迁移：默认保真，只读原文件，完整保留报告配置、图片、获准PDF、原始日期和缺口；`--mode structured` 仅生成结构化分析，不能当作保真交付。
- 论文或科普：只整理研究框架，本版不提供专用论文/科普排版器。

## 双模式选择

- 原版保真模式：接受原版 `报告.json` 的 `sources/charts/pages/blocks/attachments`。保留原标题、副标题、正文、图表标题与配置、判断、备注、引用定位及布局，支持堆叠、柱线双轴、横向柱图、散点、多图和图/文/表/图片混排。原图与获准附件随报告内嵌，不强制转表、删图或转换为结构化证据。
- 结构化模式：研究数据与报告配置分开，继续逐值核对来源、证据、单位和推理限制；横版 `visual` 保留完整正文、精简来源索引和独立完整底稿。

两种模式都拒绝危险脚本、外部资源加载、路径逃逸与未授权附件。兼容图表只允许纯文本和数值模板，不接收HTML、原始小于号或任意CSS；比较文字写“低于”，颜色、字体和尺寸采用安全格式。原版配置只作安全、结构和保真检查，
不冒称已经通过结构化证据校验；保留历史数据不等于将其升级为当前事实或业务批准。新研究可按表达需要选择模式，
但选择保真模式不能免除研究负责人对原文、数字和判断的审校。

## 研究流程

1. 读完整获准原文，明确读者用途、商业问题、地域、时期与未知范围，区分客户陈述、外部事实、判断、假设和建议。
2. 登记少量研究问题、经营用途、可回答范围及会改变判断的证据；缺材料时集中问必要信息，不替客户填写事实。
3. 外部来源发现优先用当前可用 Tavily；不可用时记录替代检索方式并继续。摘要只作线索，关键判断回官方或一手原文。
4. 按 references/研究与证据规范.md 分类登记来源与证据，保留发布日期、采集日期、统计期、原文位置和分享限制。
5. 按 references/机制与既有研究对照.md 建立可推翻假设、反例和竞争解释；比较既有研究时核对层次、对象及适用边界。
6. 形成观点卡与逐页故事线：一个判断、同组证据、替代解释、边界、经营含义和讨论动作。按 references/对客表达与审校.md 检查标题与备注。两种模式的新研究及内容修订都先读 references/成稿与保留检查.md，建立成稿核对文件和逐页图形方案，区分正文阅读与底稿核查，再决定页面结构。
7. 选择报告原型，构建并实际打开成品，逐页检查。证据不足就明确停在内部研究阶段稿。
8. 结构化模式下，新的横版咨询提报使用 `presentation_style: "visual"`；兼容模式新写报告可用 `diagram` 可重排关系图，契约见 references/报告原型与版式.md。视觉方向未确定时先做三张代表页；已确认方向且授权完整制作时直接延续，不重复索要确认。比较、步骤、条件判断分别用对比图、流程图、矩阵；不能把长文字换成卡片就当成可视化完成。历史保真交付保持原布局，不自动套用visual或重排原页。
9. 结构化visual提报末尾只放精简来源索引，常规项目1–2页。完整证据和推理存为独立的研究底稿，不占默认翻页、讲者页数和提报PDF；交付时保留同目录的底稿HTML和研究JSON，不通过删除依据来压缩页数。
10. 结构化三页代表稿设置 `delivery_scope: "preview"`；完整稿设置 `delivery_scope: "complete"`，逐项覆盖研究故事线。交付前对照原稿列出每个论点的保留位置、关键依据、推导和限制；不能以附录缩短为理由删掉正文研究内容，也不能靠重复标题或增加空泛页面凑覆盖率。

不得编造样本量、日期、数字、引语、销量或利润。一次商品观察不证明持续趋势，
少量访谈不证明总体比例，相关不等于因果。企业披露保留自报范围。
机构政策、协会材料使用 `public_document`，不贴“企业自报”标签。
没有同条件商品观察、消费者或渠道一手验证时，新品排序只能是带条件的待验证假设；
不能把宏观渠道增长和企业动作直接写成客户新品一定值得优先投入的依据。
公式仅作追溯文本，工具不执行公式；由研究负责人独立复算后登记结果和单位。

## 数据与原型

结构化模式先读 schemas/研究项目.schema.json 与 schemas/报告配置.schema.json，
参照 tests/fixtures/基础有效样本/ 的结构，不把匿名示例改名充当真实研究。

- 研究数据.json：问题、来源、证据、计算、假设、机制、既有研究、观点及故事线。
- 报告.json：引用研究编号，配置标题、正文、图表、表格、图片、备注及获准附件。
- consulting_deck：横版咨询提报，默认16:9。
- long_report / research_report：A4长报告，带实体页目录、页码及长表分页。
- survey_report：调查报告，显示题目、样本、时期和限制，适用时用大数字或分布图。

详细格式见 references/报告原型与版式.md。结构化图表支持柱、线、饼、双数值轴散点与同单位多系列柱/线；
同页可用 `charts` 展示1–3张图，不接受任意脚本或ECharts选项。需要旧堆叠、双轴或复杂混排时，
选择明确标注的原版保真契约，经安全检查保留原ECharts数据配置，不用低保真结构化转换冒充无损替代。图片支持项目内PNG/JPEG/WebP；
PDF必须明确批准分享。页数预算不是强行凑页或裁切内容的依据。
page_budget 可省略或为 null。修订研究数据时保留原稿；优先标记 rejected 而不删除。
确需删除时先在项目变更记录中写明编号、原因、操作者和日期，再改源数据，不能无痕清理。

视觉提报每个逻辑页保留一个完整论点，正文只放关键解释、图形、经营含义与限制。
完整证据和来源进入独立研究底稿，短引用仍可定位原文。超出容量时精简重复表达或拆分论点，
不能裁掉文字、压到不可读字号，或自动生成只有出处的正文“续页”。

### 客户成稿表达硬门禁

结构化报告配置可通过 `audience_mode` 明确用途，缺省为 `client`。`client` 是客户可见成品，
必须通过本节全部表达检查；`internal` 仅用于内部研究底稿或技术回归，须在成品清单中标注，
不得作为客户交付，也不得导出客户 PDF。旧版兼容构建默认始终按客户用途检查。

研究底稿可以记录“查了什么、没查什么、哪条外链未复核、哪项研究尚未执行”；
客户可见的 PPT、PDF、HTML 页面和讲者台不能出现这些内部工作状态。
以下内容必须进入独立反馈或研究底稿，不能进入客户页面：

- “现有资料不能给出中保市场规模”
- “仅核对本地摘录”“外链未复核”“未取得外部原文”
- “本次未执行”“研究缺口尚未补齐”“客户尚未确定”
- “上版完整页面”“固定输入”“本轮重排前”“完整研究底稿”等制作过程说明

客户页要改写成三件事：当前证据支持什么、对经营决策有什么影响、下一步要验证什么。检查必须跟随实际渲染字段：视觉模式页面会显示观点卡边界、经营含义及限制说明，即使配置了正文也要逐项扫描；讲者备注也须检查。新增发现的漏检表达要固化为回归测试，不可只修当前项目文字。
例如把“现有资料不能给出中保市场规模”改成“不同统计口径暂不能合并估算中保容量”，
或“中保容量需按保质期、品类与渠道拆分后再估算”。
讲者备注也不得残留“本展示页”“本轮未重新法规核验”等制作标记或研究执行状态；改写为适用法规要求和下一步验证动作。

每次生成客户可见的 HTML、PDF、讲者台或逐页备注前，都必须执行这项检查；`internal_draft`、
`client_discussion`、`formal_delivery` 及 `preview`/`complete` 均不能豁免。状态只说明研究或覆盖进度，
不代表内部话术可以进入成品。纯内部研究底稿可保留完整审计过程，但必须与客户成品分开；
将内部底稿重新设为 `client` 后，仍须完整扫描，不能借切换用途绕过门禁。
命中时构建直接阻断，并在项目目录生成 `成稿表达反馈.json`，列出页码、字段、命中原句、
问题和建议；反馈保留必要上下文并合并重复项，不把内部问题塞进交付物。
进入客户交付的 HTML、PDF、页面、来源说明和讲者台都不能包含内部制作话术；需要补资料或确认口径时，写入反馈并向用户提出。
证据适用边界属于业务内容，可以保留；例如“不能把不同统计口径直接相加”不等于内部制作过程话术。

## 构建与验收

先确认 Node、Playwright/Chromium 和 Python/PyMuPDF可用，配置见安装文档。
在包根目录执行，将示例路径替换为真实项目路径：

原版项目目录调用保持兼容，项目内有 `报告.json` 及其本地素材即可，不要求补造研究数据：

```sh
node scripts/构建报告.cjs /项目 --production historical_replay
node scripts/验收报告.cjs /项目
python3 scripts/检查PDF.py /项目
```

原版配置也能用于新写或内容修订，但必须显式使用 `--production new_report` 或
`--production content_revision`，同时提供结构化研究底稿和逐页图形方案；不能因为输入格式兼容旧版就按历史回放放行。

后两条均走统一验收；Python项目目录调用会重跑浏览器/PDF及指纹检查，不是绕过包装的独立写入。
构建产物在 `/项目/交付`。已有交付不直接覆盖；旧版未登记产物请保留并改用新的独立输出目录。

结构化模式：

```sh
node scripts/验证研究数据.cjs /项目/研究数据.json /项目/报告.json
node scripts/检查图表方案.cjs --plan /项目/逐页图形方案.json --research /项目/研究数据.json --report /项目/报告.json
node scripts/构建报告.cjs --research /项目/研究数据.json --report /项目/报告.json --out /项目/交付 --production content_revision --plan /项目/逐页图形方案.json
node scripts/验收报告.cjs /项目/交付 --review /项目/图表占比登记.json
```

`逐页图形方案.json` 必须先覆盖预计全部物理页，包括自动目录、来源索引、结尾和合并附录。
每页填写结论、证据或有边界的待验证假设、图形形式、真实维度、使用的数据或关系材料、读图所得、必要解释、经营含义、客户页限制、预计分类和理由。
`mode` 只接受 `new_report` 或 `content_revision`，并须与报告 `production_mode` 一致；封面、目录、来源索引和结尾不能计入合格页。
预检按 `ceil(2N/3)` 计算最低线，并至少多留1页余量。未通过时停在方案阶段，不生成HTML/PDF。

默认不覆盖。确认重建才加 --overwrite，旧交付保留为相邻备份。
被手改成品、未知文件、项目外资料或指向技能包的输出会被拒绝。
输入、图片、附件或工具版本变化必须重建，不能沿用旧验收。

输出：案前洞察.html、案前洞察.pdf、逐页讲解备注.md、研究数据.json、视觉模式的研究底稿.html、
成品清单.json与验收目录。HTML直接离线打开，无需服务器；讲者台在独立窗口运行。
原版模式的 `研究数据.json` 保存原报告配置，不是结构化证据底稿；可选研究输入另存为 `结构化研究底稿.json`，不因此获得证据批准。

## 交付门槛

- 图表主导页硬门槛：新写或内容修订的完整主报告，按最终全部物理页N计算，合格图表主导页G须满足 `3 * G >= 2 * N`，33页至少22页。封面、目录、来源、结尾及合入主报告的附录均计入N；独立底稿不计。一页多图只计一页。统计图或表达实质关系的流程/矩阵等可以计入；文字分栏、彩色卡片、纯文字表格与装饰图不计。构建后逐页实际看，登记理由与版本，独立复核；未登记、待确认或比例不足不得判成稿完成。完整口径见 references/图表占比验收.md。机器预检只检查方案完整性、证据编号、预计比例和余量，不理解图形语义；最终统一验收会读取真实HTML/PDF页数与当次登记。方案与最终页序不一致、登记无效或任一格式不足时交付状态保持阻断。纯转换和历史保真回放不擅自重排，也不冒充新稿质量达标。
- 新研究与内容修订先运行 `node scripts/检查呈现.cjs --report /项目/报告.json --checklist /项目/成稿核对.json`，再独立核对原问题子项和实际页面；连续表格、图片小字、未回答及舍弃项的提示不能隐去。预检只读，退出0不代表语义覆盖或业务批准。历史保真回放不强制补造清单。
- 实际逐页审校后，按`references/图表占比登记格式.md`填写`图表占比登记.json`。可单独运行`node scripts/检查图表占比.cjs --project /项目 --review 图表占比登记.json`排查，也可由统一`验收报告.cjs --review`执行正式门禁。退出0仅说明登记、指纹和比例通过，1为不足，2为登记无效；仍须真实独立视觉审校，不能虚填记录或把组件检测当实质图表判断。`technical_passed`仍只表示机械检查，不是交付完成。
- fatal：结构、引用、数字、授权、指纹或实际渲染错误，修复并重验。
- warning：保留缺口和限制，不隐去不利信息。
- technical_passed：仅表示实际浏览器/PDF/指纹机械检查通过，不代表研究事实真实。
- 内容与视觉仍须单独审校：回原文复核数字和推理，实际查看桌面、手机及PDF截图。
- 逐页问：读者能否从图形直接看出比较关系、步骤或条件？只有文字块和装饰线不算图形表达。正文密度统计排除页眉页脚，指标只筛出疑似稀疏页，不自动证明专业度。
- 以旧版能力和原研究为质量基线：正文必须讲清“依据是什么、为何得到这个判断、对客户意味着什么、什么条件下不成立”。独立底稿不能替代这四项；完整性门禁只检查故事线覆盖，不能证明内容深度或事实真实。
- 引擎自检不等于整包替换验收完成。须通过旧入口、两份真实食品报告、图文附件样本回放、完整回归与独立复审，替换前备份到技能发现路径之外；完成后从稳定旧入口与v2的实际安装目录分别构建和验收。缺项时继续标记候选，不宣称替换成功。客户实测信息只留项目回归记录，不进入公开包。
- 工具只能阻止已知的过度断言，不能理解并核实所有自然语言。没有命中规则不等于结论真实。

## 匿名测试与历史回归

```sh
node scripts/生成演示项目.cjs /独立目录/横版 deck --attachment
node scripts/生成演示项目.cjs /独立目录/长报告 long
node scripts/生成演示项目.cjs /独立目录/调查 survey
node --test tests/*.test.cjs

# 旧说明中的测试命令仍可用，样本目录必须为空
node scripts/测试样本.cjs /独立空目录/旧版样本
node scripts/制作附件测试.cjs /独立空目录/附件样本
node --test scripts/构建测试.cjs
```

生成后按构建和验收步骤执行。设置 RUN_DELIVERY_TESTS=1 可运行完整交付测试，
需要浏览器和PDF运行时；缺依赖导致跳过不算通过。
历史迁移默认保真：`node scripts/迁移研究数据.cjs --input /原资料/报告.json --out /新目录`。
`报告.json` 与所需本地资产保留，结构化分析另存；仅需分析时另选新目录并加 `--mode structured`。
后者可能存在图形与资产保真缺口，不能替代原报告。读取迁移缺口，保留历史日期，不伪造公式、证据和批准。
旧结构化映射细节见 references/历史回归说明.md；双模式选择与当前迁移默认值以本节及 references/报告原型与版式.md 为准。
