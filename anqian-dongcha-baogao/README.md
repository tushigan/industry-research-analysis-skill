# 行业调研分析（新版）

`0.6.0` 本地图表规划与交付门禁版说明。实际包版本以 `VERSION.json` 为准，安装与替代检查结果以当次回执为准。
文档不代替实际验收，也不自动替换已安装包。

研究规则以 [SKILL.md](SKILL.md) 为入口。包内提供两种输入模式，共用本地运行时和随包静态依赖：

- **原版保真**：内置兼容引擎，不调用外部旧安装包。保留原图配置、原标题与副标题、正文、图表标题、判断、备注、引用和布局；支持堆叠、柱线双轴、横向柱图、散点、多图、图文表图片混排、原图与获准PDF附件，以及原项目目录命令。
- **结构化研究**：保持严格的证据、来源、逐值数字、单位与限制校验。`visual` 横版保留完整论点和经营含义，末尾精简来源索引，详细证据和推理保留为独立完整底稿，不靠删正文缩短报告。

两种模式都提供离线HTML、同版PDF、逐页备注、讲者双向同步和布局恢复、获准附件阅读、指纹与覆盖保护。
新研究共用成稿覆盖与对客表达规则，兼容模式可使用手机重排的步骤、任务比较和机会条件图；历史输入未选用新图形时保持原布局。详见 [成稿与保留检查](references/成稿与保留检查.md)。
原版模式的安全和保真检查不等于结构化证据核验；历史数据、日期和缺口不会自动升级为当前事实或业务批准。

## 本地运行

在包根目录执行，输入和输出放在独立项目中。主入口根据 `报告.json` 的输入契约选择模式，不要求旧报告伪造结构化研究数据。

### 原版项目目录命令

```sh
node scripts/构建报告.cjs /项目
node scripts/验收报告.cjs /项目
python3 scripts/检查PDF.py /项目
```

项目内保留原 `报告.json`、图片和获准PDF，输出到 `/项目/交付`。若当前目录为包内 `scripts/`，命令仍为
`node 构建报告.cjs /项目`、`node 验收报告.cjs /项目`、`python3 检查PDF.py /项目`。
Python项目目录入口调用统一验收，会重新执行浏览器/PDF及指纹检查。主验收也接受交付目录。
默认不覆盖；`--overwrite` 只用于确认重建，不能覆盖未登记或被手改的旧交付，遇到这类文件请使用新输出目录。

### 指定输入与输出

原版配置不必传 `--research`：

```sh
node scripts/构建报告.cjs --report /原资料/报告.json --out /独立目录/保真交付
node scripts/验收报告.cjs /独立目录/保真交付
```

高级接口同样允许原版省略 `researchPath`：

```js
const { buildReport } = require('./scripts/构建报告.cjs');
buildReport({ reportPath: '/原资料/报告.json', outputDir: '/独立目录/保真交付' });
```

传入可选研究文件时只作独立底稿留存，不代表原版报告已通过逐值证据校验。结构化模式仍必须提供 `researchPath`，CLI对应 `--research`。

### 结构化匿名样本

```sh
node scripts/生成演示项目.cjs /独立目录/演示 deck --attachment
node scripts/构建报告.cjs --research /独立目录/演示/研究数据.json --report /独立目录/演示/报告.json --out /独立目录/演示/交付
node scripts/验收报告.cjs /独立目录/演示/交付
```

样本原型为 deck、long、survey，均为虚构技术数据，不是原版/结构化两种输入模式，也不代表真实研究。
HTML可直接离线打开，不需要服务器。报告中讲者台按钮打开独立窗口。

## 历史迁移

```sh
node scripts/迁移研究数据.cjs --input /原资料/报告.json --out /新的保真项目
node scripts/迁移研究数据.cjs --input /原资料/报告.json --out /新的分析项目 --mode structured
```

默认 `preserve`：原 `报告.json` 与所需本地图片、获准PDF保留，结构化研究、分析报告和迁移缺口另存，不以转表或删图替代原表达。
`--mode structured` 仅用于结构化分析，可能存在图形、正文和资产保真缺口；检查缺口并补证，不把它称为无损迁移或直接交付。
两种迁移均只读原资料，拒绝覆盖已有输出；迁移成功不表示历史事实已更新、证据重核或业务获批。

## 检查

新研究或内容修订先核对问题子项、必要旧内容和页面位置：

```sh
node scripts/检查呈现.cjs --report /项目/报告.json --checklist /项目/成稿核对.json
```

此命令只读；退出0不等于语义覆盖和视觉批准。连续表格、图片阅读与未知项仍需独立审校。

```sh
node --test tests/*.test.cjs
RUN_DELIVERY_TESTS=1 node --test tests/*.test.cjs
python3 公开仓库扫描.py
```

完整交付测试需要 Playwright/Chromium 和 PyMuPDF，配置见安装文档。
缺运行时的跳过不算实际通过。DELIVERY_ARTIFACT_DIR 可指定保留证据的空目录；
否则测试使用并清理自建临时目录。

## 边界

机器检查结构、引用、数字对应、安全、渲染和版本一致性，不证明所有事实与计算正确。
历史数据保留日期和缺口；论文/科普专用渲染不在范围内。
第二真实项目、人工内容审校与业务确认必须有单独证据。
实现不等于替换验收通过：须完成旧命令、两份真实报告及图文附件样本的保真回放、完整回归与独立复审。
获准替换前保留现有安装；通过后先将原包备份到技能发现路径之外，再让稳定旧入口 `anqian-dongcha-baogao` 与v2入口使用同一套实现，并从两个实际安装目录分别构建和验收。恢复路径与操作步骤见 [安装与MCP配置.md](安装与MCP配置.md)。
不自动发布、上传、发客户或配置外部密钥。客户资料和本地回归产物不得复制进包内。
